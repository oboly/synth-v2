# Breath Curve Phase Calibration v2

Status: research-only  
Layer: market-only / account-agnostic  
Broker calls: none  
Broker writes: none  
Orders: none  
DB writes: none  

## Purpose

Calibrate Breath Curve phase-offset logic after fine-offset testing showed exact offset matching is too brittle.

The goal is to compare:

- exact offset match
- offset distance buckets
- harmonic band match at multiple widths
- selected partial offset band
- best full offset band
- extension behavior by band

## Why v2 exists

Fine-offset testing with 0.5-day offsets showed:

- 0.618 remains useful as recognition
- 0.786 remains weaker as recognition but useful for overflow diagnostics
- exact offset_match collapses under finer offset resolution
- selected partial offsets often differ from best full offsets
- the difference may still be valid if both offsets sit in nearby harmonic bands
- +5/+7 appears more extension/overflow-like
- +9/+10.5 appears more late drift / stretched phase-like

Therefore, v2 evaluates band-level and distance-level phase coherence.

## Input

Input is a Breath Curve partial-to-full CSV, usually generated by:

    python -m src.research.backtest_breath_curve_partial_to_full_v1 \
      --offsets="-10.5,-10,-9.5,...,10,10.5"

Required columns include:

- symbol
- checkpoint_ratio
- selected_partial_offset_days
- best_full_offset_days
- selected_partial_score
- same_offset_full_score
- best_full_score
- return_to_1000_pct
- return_to_1272_pct
- offset_matches_best_full

## Harmonic bands

Default band centers:

    -10.5, -9, -7, -5, -3, 0, +3, +5, +7, +9, +10.5

Default band widths:

    0.5, 1.0, 1.5 days

## Output

Generated outputs are written under:

    data/research/breath_curve_phase_calibration_v2/

Outputs include:

- annotated rows with distance and band-match fields
- distance bucket summary
- band-match summary
- selected-band summary
- best-full-band summary
- selected-to-best band cross table
